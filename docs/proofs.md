# What proves each promise

A standing map from each promise the Hub makes to what shows it today (C169). The promises themselves are written elsewhere and are not repeated in full here: the delivery guarantees in [protocol.md](protocol.md) §4, and the card states in [design.md](design.md) §3.15 "Card states". Proofs used to be attached only to changes (an item's done-when lines and its closed record); this file is where they stay after the close.

How to read and keep it:

- A proof is one of: a test (`file`, then the test's name in quotes), a `ui:check` scene (`tools/dev/ui-check.mjs`, named by the fixture Mailbox and the card text the scene expects), or a design.md §6 entry with the version it was observed with.
- A row with no proof says `none`. Nothing is invented to fill it. The `none` rows and the "Leaves out" column are the material later items work from (C170, C171, and the planning session).
- "Leaves out" says what the proof does not show of the promise as worded. An example test shows the cases it runs, not the inputs nobody thought of.
- A row is added or corrected when a guarantee changes (protocol.md §4, design.md §3.15), when a test named here is renamed or removed, and when an incident recorded in design.md §6 shows a promise broke or was never checked: the incident adds a row, or corrects the proof of one (design.md §1.2, "Incidents in §6 become new verification angles").
- `npm run docs:check` warns when a file named in backticks here (`src/…`, `tools/…`) does not exist. It does not check the test names or what a test asserts; that is read by a person.
